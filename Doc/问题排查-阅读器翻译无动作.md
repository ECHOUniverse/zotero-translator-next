# 问题排查经验：阅读器翻译"点击无动作"（v0.4.0 回归）

> 记录时间：2026-08-13
> 影响版本：v0.4.0（`ff48b72` 引入回归）
> 修复版本：v0.4.1（`c1dba90`）
> 关联文档：[`PLAN.md`](./PLAN.md)、[`Zotero9-阅读器插件开发方法.md`](./Zotero9-阅读器插件开发方法.md)

---

## 1. 问题概述

**现象**：PDF 阅读器中划选文本后点击弹层"翻译选中内容"按钮，侧栏毫无反应——无"翻译中"状态、无译文卡片、历史区仍显示"暂无翻译历史"。主窗口"翻译选中条目"按钮正常。

**用户关键线索**："上个版本还没问题，这个版本出现的这个问题" → 确认是回归，问题出在 v0.4.0 引入的改动中。

**结论**：`ff48b72`（侧栏历史按文章隔离）新增的"结果卡片条目隔离"逻辑与阅读器场景的 itemID 语义错位——任务 itemID（附件 id）≠ 区块 ctx.itemID（父条目 id）恒成立，导致翻译成功后卡片被替换回空态，表现即为"无动作"。

---

## 2. 根因分析（证据链）

### 2.1 代码逻辑

v0.4.0 在 `renderResultCard()` 新增条目隔离（D10 语义）：

```ts
// src/ui/sections.ts
if (
  task &&
  ctx.itemID != null &&
  task.itemID != null &&
  task.itemID !== ctx.itemID
) {
  box.replaceChildren(emptyState(doc, getString("ztr-empty-result")));
  return; // ← 显示空态，结果"消失"
}
```

翻译入口（阅读器弹层/快捷键）：

```ts
// src/modules/reader.ts
translate({ sourceText, itemID: reader.itemID ?? null, ... })
// reader.itemID = PDF 附件的 item id
```

### 2.2 Zotero 侧语义（源码核查，Zotero 9.0.6）

**区块收到的 item 是父条目，不是附件**。`contextPane.js` 的 `_addItemContext()`：

```js
let targetItem;
if (item.isNote()) {
  targetItem = item;
} else {
  targetItem = parentID ? Zotero.Items.get(parentID) : item; // 附件 → 提升为父条目
}
...
itemDetails.item = targetItem; // 区块 ctx.itemID 来自这里
```

**配套佐证**：`ZoteroPane.getSelectedItems()` 在 `tabContentType === 'reader'` 时同样把附件提升为父条目。

### 2.3 错位推导

| 来源 | itemID | 值 |
| --- | --- | --- |
| 翻译任务 `task.itemID`（reader.ts） | `reader.itemID` | **附件 id**（如 123） |
| 区块 `ctx.itemID`（ItemPane 上下文） | item 提升后 | **父条目 id**（如 100） |

`task.itemID !== ctx.itemID` 恒成立 → 每次翻译成功，卡片立即被空态替换。历史区同理：落库用附件 id（`addHistory({ itemID: task.itemID })`），查询用父条目 id（`getHistoryByItem(ctx.itemID)`），永远查不到 → "暂无翻译历史"。

**为何测试未捕获**：集成测试（`startup.test.ts`）只覆盖主窗口场景——选中条目即翻译条目，两侧 id 一致，隔离逻辑不触发。阅读器场景完全未覆盖。

---

## 3. 修复方案

**统一"逻辑条目"语义**：翻译任务 itemID 一律归一化为父条目 id（无父条目时回落附件 id），与区块上下文、历史按文章隔离、总结笔记归属全部对齐。

```ts
// src/modules/reader.ts —— 新增
/**
 * 附件 → 父条目（逻辑条目）id。
 * 阅读器 tab 中 ItemPane 上下文向区块提供的 item 为父条目（Zotero contextPane
 * 会把附件提升为 parentItem），而 ReaderInstance.itemID 是附件 id。若翻译任务
 * 直接落附件 id，与区块 ctx.itemID 不一致：条目隔离渲染/历史按文章查询都会错位
 * （表现为翻译成功但卡片不显示、历史区空）。统一归一化为父条目 id。
 */
function logicalItemID(
  readerItemID: number | null | undefined,
): number | null {
  if (readerItemID == null) return null;
  try {
    const item = Zotero.Items.get(readerItemID);
    // Zotero 类型中 parentID 为 number | false（无父条目时 false）
    const parentID = item?.parentID;
    return typeof parentID === "number" ? parentID : readerItemID;
  } catch {
    return readerItemID;
  }
}
```

三个入口统一使用：弹层按钮点击、划选即译、快捷键 `translateSelection()`。

**注意**：`Zotero.Item.parentID` 类型为 `number | false`（无父条目时 `false`），不能用 `??` 直接回落，需 `typeof === "number"` 判断（TS 2322 编译错误教训）。

## 4. 排查过程（方法学）

### 4.1 定位路径

1. **用户反馈 + 截图**：侧栏空闲态（MyMemory 引擎、"暂无翻译历史"）→ 确认是阅读器区块场景，无任何报错。
2. **用户补充"上个版本正常"** → 转向版本对比，锁定 `ff48b72` 的新增逻辑。
3. **源码审查** `renderResultCard` 隔离逻辑 → 提出 itemID 错位假设。
4. **Zotero 源码核查**（解包 `omni.ja` 读 `contextPane.js`）→ 确认"区块 item = 父条目"。
5. **集成测试复现**：真实 PDF 打开阅读器 → 翻译 → 断言卡片显示 → 修复前失败、修复后通过。

### 4.2 关键技巧

- **用户的一句话比十次猜测有用**："上个版本正常"直接指回归方向。
- **Zotero 行为以源码为准**：`/Applications/Zotero.app/Contents/Resources/app/omni.ja` 是 zip，`unzip -l` + 解出 `contextPane.js` / `itemPaneSection.js` / `itemDetails.js` / `reader.js` 逐行核实，避免猜 API 语义。
- **隔离逻辑 + 私有字段的组合**：区块 `ctx.itemID` 是插件内部状态，测试中通过 DOM 区块属性与任务字段交叉验证。

## 5. 沉淀：Zotero 9 阅读器架构要点（排查中确认）

> 均为本次排查中解包源码验证的事实，供后续开发直接引用。

### 5.1 itemID 语义矩阵

| 场景 | 上下文提供的 item | 说明 |
| --- | --- | --- |
| 主窗口 library tab | 选中的条目（原样） | 附件/论文均可被选中 |
| 阅读器 tab（context pane） | **父条目**（附件提升） | `contextPane.js _addItemContext` |
| `ReaderInstance.itemID` | 附件 id | 注意与上一条不同 |
| `ZoteroPane.getSelectedItems()`（reader tab） | 父条目 | `zoteroPane.js` 同样提升 |

**推论**：任何"按条目隔离/按文章查询"的功能，任务与 UI 两侧必须统一用父条目 id。

### 5.2 item-details 渲染条件

`itemDetails.render()` 会**跳过区块渲染**，当：

- `this.initialized` / `item` 为空
- `skipRender`（等待中）
- **`_collapsed`（侧栏折叠）** ← 测试环境默认折叠，区块保持骨架（`bodyXHTML` 已注入但工具栏/空态未渲染），`onRender` 不触发、`ctx.rendered` 恒为 false

**推论**：区块的 `subscribe` 回调以 `ctx.rendered` 为前置条件——侧栏折叠时翻译结果不实时渲染，属预期（展开时 `getLatestTask()` 会补渲染）。

### 5.3 阅读器 DOM 结构（三层）

```
Zotero 主窗口（主进程，Zotero.Tabs）
└── reader.html（resource://zotero/reader/reader.html，Zotero React 前端）
    └── iframe → viewer.html（resource://zotero/reader/pdf/web/viewer.html，pdf.js）
        └── #viewer .page .textLayer span（文本层）
```

- 划选弹层（SelectionPopup）渲染在 **reader.html**；文本层在 **viewer.html**。
- **XRay 包装**：主进程访问嵌套 iframe 必须 `Components.utils.waiveXrays(contentWindow)`，且在目标 realm 内 `eval` 才能无阻碍读写（直接属性访问会得到 wrapped 对象/undefined）。
- pdf.js 状态入口：`viewerFrame.contentWindow.PDFViewerApplication`（需 waiveXrays），`pdfViewer.getPageView(0).textLayer` 可诊断文本层。
- **文本层渲染与 PDF 内容流强相关**：内容流损坏（如 base64 转存错误）时 canvas 能渲染但文本层为空、`getTextContent()` 抛 "Bad encoding in flate stream"。

## 6. 沉淀：集成测试环境陷阱清单

`zotero-plugin test`（scaffold + Playwright 启动真实 Zotero）的坑：

| # | 陷阱 | 现象 | 对策 |
| --- | --- | --- | --- |
| T1 | **测试内嵌 base64 手工复制易损坏** | 文本层不渲染、"Bad encoding in flate stream" | 用脚本替换/校验 base64（md5 对比原始文件） |
| T2 | **翻译缓存跨运行命中** | 固定文本第二次运行缓存命中（不落库、任务瞬态结束），历史断言失败 | 测试文本追加 `Date.now()`；或关闭 `prefs.cacheEnabled` |
| T3 | **缓存命中任务不可轮询** | `getCurrent()/getQueued()` 取不到已结束任务 | 用 `translate.subscribe()` 收集任务 |
| T4 | **阅读器侧栏默认折叠** | 区块不渲染（工具栏空、结果区空），`ctx.rendered=false` | 点击 `sidebarToggle` + `itemDetails._collapsed = false` + 强制 `await itemDetails.render()` |
| T5 | **错误信息经 HTTP 序列化丢失** | mocha 失败只显示 `Expected: undefined / Received: undefined` | 断言消息内联诊断字段；用 scaffold 的 `window.debug()` 通道输出步骤日志 |
| T6 | **Zotero 测试 profile 持久化** | 多次运行共享数据库/侧栏状态 | 状态相关断言要幂等（如随机文本、显式展开侧栏） |
| T7 | **fixture PDF 生成** | reportlab 生成单页文本 PDF（1.5KB）内嵌测试文件 | base64 内嵌避免 node 模块依赖（esbuild 不能 bundle node builtin） |

## 7. 预防措施（防再犯）

1. **itemID 语义单一来源**：任务/历史/UI 三处统一"逻辑条目 id"；新增按条目隔离功能前，先核对 Zotero 侧 `itemDetails.item` 的实际条目类型（源码为准）。
2. **阅读器场景测试常驻**：`test/reader-selection.test.ts` 保持为回归护栏——真实 PDF → 阅读器 → 翻译 → 断言（任务关联父条目 + 卡片显示 + 历史按文章落库）。
3. **测试环境断言顺序**：核心断言（数据层）放在 UI 断言之前，UI 渲染依赖窗口状态时避免"一步失败全盘失败"。
4. **发布前检查**：改 UI 状态语义（隔离/过滤/归属）时，跑全量集成测试 + 手动验证阅读器划选链路。
