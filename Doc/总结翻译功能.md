## 1. 需求定义

**用户原始诉求**：总结翻译功能还没实现。

**澄清后的需求定义**（grilling 会话确认）：

> 对获得的翻译文本进行梳理，总结核心内容、观点、方法等，然后输出，服务于学术研究。

即：翻译结果 → AI 结构化总结（研究问题 / 方法 / 主要发现 / 结论 / 局限）→ 可复制、可入历史、可写入文献笔记。

**与 PLAN.md §10 的关系**：本功能即 PLAN §10"AI 总结"的实现落地。方案主体代码已存在，本次更新解决"入口不可见 + 三处未完成点 + 消费出口缺失"。

## 4. 详细设计

### 4.1 入口与可见性（D2）

- **翻译成功卡片**（`sections.ts`）："AI 总结"按钮由"LLM 可用才渲染"改为**常驻**。
  - LLM 可用：正常触发总结流程（现状行为不变）。
  - 无 LLM：按钮可点击，点击后弹 Zotero 原生提示（"总结功能需要配置 DeepSeek 或自定义 OpenAI 渠道"），带"打开设置"按钮直达偏好面板。
- **历史条目卡片**（D3）：新增"总结"按钮（图标按钮，与删除并列），显隐规则同上。
- `hasAvailableLLM()` 逻辑保留（判断条件不变），仅改变按钮渲染策略。

### 4.2 总结流程重构（`sections.ts` `runSummary`）

- 签名改为**可指定任务**：`runSummary(ctx, task)`（现状已接收 task，历史条目复用同一函数）。
- 总结卡片结构：状态徽章 + 流式文本 + 操作区。
- 操作区按钮（D5）：
  - **复制**：`copyText(summary)` 一键复制总结文本；
  - **存入历史**：现有 `saveSummaryToHistory`（按 `formattedText` 哈希查历史条目写入 `summary` 字段）；
  - **写入笔记**：调 `SummaryManager.saveNote(itemID, summary)`；`task.itemID` 为 null 时按钮禁用（tooltip 说明）；
  - **重新生成**：重新调用 `summarize()`（清空当前卡片重跑）。
- **历史条目总结**（D3/D10）：点击历史条目卡片上的总结按钮 → 在该条目卡片**下方内联展开**总结卡片（跟随条目，多条历史可各自总结，互不串台）；操作按钮与最新任务一致。
- 总结容器：最新任务用现有 `#ztr-*-summary` 容器；历史条目用内联容器（新 DOM，复用 `.ztr-card` 样式类）。

### 4.3 `SummaryManager` 增强（`src/modules/summary.ts`）

- **`buildPrompt()` 可测化**：从默认模板/自定义提示词构建 system prompt，进行 `{targetLang}` 插值（用 `src/utils/lang.ts` 语言名映射：zh-CN → 中文，en-US → English；映射缺失时回退原文代号）。
- **默认提示词**（D7，中文结构化模板）：

  ```
  你是学术助理。请用 {targetLang} 对以下翻译文本进行结构化总结：
  ## 研究问题
  ## 研究方法
  ## 主要发现
  ## 结论
  ## 局限（如原文提及）
  控制在 300 字以内，基于文本内容，不要编造。
  ```

- **新增 `saveNote(itemID, summary)`**（D8）：
  1. `itemID` 为 null → 抛错/返回（UI 层已禁用按钮，双保险）；
  2. 取条目笔记：遍历 `item.getNotes()`，解析 note HTML 首行标题，查找固定标题 **"AI 总结"**；
  3. 存在 → `note.setNote(新HTML)` 覆盖更新（保留原 noteID）；
  4. 不存在 → `Zotero.Items.addNote(itemID)` 新建；
  5. 笔记正文格式：`<h1>AI 总结</h1><p>…总结文本…</p>`（Zotero 笔记标题取自首个标题元素）。
- **输入长度**（D9）：`summarize()` 全量发送，不截断。
- **语言**（D4）：`summarize()` 读取 `prefs.summaryLang`（默认 `"auto"` → 跟随 `prefs.targetLang`），传入 `buildPrompt()`。

### 4.4 快捷键补全（D6，`src/modules/reader.ts`）

- `summarizeLastSelection()` 空壳补全，**架构：回调注入，避免模块反向依赖 UI**：
  - `ReaderModule` 构造器新增可选参数 `onSummarize?: (task) => void`；
  - `addon.ts` 装配时注入 `sections` 暴露的"对最近成功任务触发总结"函数；
  - 快捷键按下 → 取最近成功任务（`TranslateManager` 的当前/最近任务）→ 有则回调，无则提示"暂无已翻译内容"。
- 触发结果渲染到对应窗格（阅读器快捷键作用于阅读器窗格；主窗口按键作用于条目窗格）。

### 4.5 设置面板（D4/D7，`preferences.xhtml` + `prefs.ts` + locale）

- `prefs.ts` 新增 `summaryLang`（`get`/`set`，默认 `"auto"`，键 `summary.lang`）。
- `preferences.xhtml` 新增"总结"配置区块：
  - **总结语言**：下拉（跟随目标语言 / 中文 / 英文 / 自定义）；
  - **总结模型**：输入框（留空 = 使用当前 LLM 渠道默认模型，覆盖 `summary.model`）；
  - **总结提示词**：多行 textarea（留空 = 默认结构化模板，覆盖 `summary.prompt`）。
- locale：`zh-CN/preferences.ftl`、`en-US/preferences.ftl` 新增对应文案；`addon.ftl` 新增"打开设置/复制总结/写入笔记/重新生成"等按钮文案。
- 设置面板脚本注意 Zotero 8+ 独立 global scope 约束（现有代码已遵守，新代码同规则）。

### 4.6 数据与接口

| 接口                           | 说明                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| `prefs.summaryLang`            | 新增，`"auto"` 或具体语言代号（如 `zh-CN`、`en-US`）         |
| `prefs.summaryModel`           | 已有（`summary.model`），本次补 UI                           |
| `prefs.summaryPrompt`          | 已有（`summary.prompt`），本次补 UI + 插值修复               |
| `history.itemID`               | 已有（可空 INTEGER），写笔记定位依据；无关联条目时禁用写笔记 |
| `SummaryManager.buildPrompt()` | 新增，纯函数可单测                                           |
| `SummaryManager.saveNote()`    | 新增，笔记写入/更新                                          |

## 8. 风险与对策

| 风险                                                              | 对策                                         |
| ----------------------------------------------------------------- | -------------------------------------------- |
| Zotero 9 笔记 API 差异（`getNotes`/`addNote`/`setNote` 行为变化） | 实施前对照官方文档；真机验收优先验证笔记读写 |
| 超长文本（1M 上下文内的 token 计费成本）                          | 先全量，实测超长场景再决定是否加字符上限保护 |
| 快捷键与 Zotero 内置/其他插件冲突                                 | 快捷键本就可在设置中修改/关闭（已有）        |
| 历史条目 `itemID` 为 null（未关联条目或条目已删）                 | 写笔记按钮禁用；总结/复制/存历史不受影响     |
| 默认提示词对非学术文本（新闻/信件等）不适用                       | 用户可在设置面板自定义提示词                 |
